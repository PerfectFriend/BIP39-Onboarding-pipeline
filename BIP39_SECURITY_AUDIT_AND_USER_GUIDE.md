## 2. Полный отчет об аудите безопасности (Security Audit Report)

### 2.1 Криптографическое ядро BIP-39
* **Генерация энтропии:** Выполняется строго на клиенте с помощью криптографически стойкого аппаратного CSPRNG (`crypto.getRandomValues`).
  * Для 12 слов: $128\text{ бит}$ (16 байт) исходной энтропии $+ 4\text{ бита}$ SHA-256 контрольной суммы $= 132\text{ бита}$ (12 слов по 11 бит).
  * Для 24 слов: $256\text{ бит}$ (32 байта) исходной энтропии $+ 8\text{ бит}$ SHA-256 контрольной суммы $= 264\text{ бита}$ (24 слова по 11 бит).
* **Словарь:** 2048 слов официального канонического словаря BIP-39 English Wordlist.
* **Деривация Seed:** Функция деривации ключа PBKDF2 HMAC-SHA512 с 2048 итерациями, солью `mnemonic` (плюс опциональный пароль) и обязательной NFKD-нормализацией строк.
* **Изоляция:** Нет ни одного сетевого вызова, логирования или передачи seed-фразы на внешние эндпоинты.

### 2.2 Защита хранилища (AES-256-GCM & PBKDF2)
* **Алгоритм шифрования:** Нативный WebCrypto `AES-GCM` (256-битный ключ).
* **Вектор инициализации (IV):** Случайный 12-байтный одноразовый вектор (nonce) на каждую операцию сохранения.
* **Деривация ключа шифрования:**
  * Алгоритм: `PBKDF2` со случайной 16-байтной солью и хеш-функцией `SHA-256`.
  * Количество итераций: **100 000 итераций**.
  * Обоснование: делает атаку методом полного перебора (brute-force) 4–6 значного PIN-кода вычислительно нецелесообразной при извлечении зашифрованного payload из браузера.
* **Политика Zero-Plaintext:** Ни мнемоника, ни seed, ни деривированные приватные ключи никогда не сохраняются в `localStorage`, `sessionStorage`, `IndexedDB` или cookies в открытом виде.

### 2.3 Модель угроз и Панический PIN (Duress Threat Model)
* **Атака физического принуждения ($5 Wrench Attack):**  
  Криптографические ключи бессильны, если пользователя принуждают ввести PIN-код под физической угрозой или при незаконном досмотре.
* **Решение:** Внедрен альтернативный **Панический PIN-код (Duress PIN)**.
  1. Панический PIN хэшируется с солью через SHA-256. В зашифрованном манифесте хранится только хэш: злоумышленник не может определить его наличие и отличие от основного PIN.
  2. При вводе этого кода срабатывает аварийная процедура `wipeAllVaultData()`:
     * Мгновенная очистка `localStorage` и `sessionStorage`.
     * Физическое удаление баз данных `IndexedDB`.
     * Обнуление структур в оперативной памяти (RAM zeroization).
  3. Происходит мгновенный возврат приложения в начальное состояние, как будто кошелек никогда не создавался.

### 2.4 Защита от перехвата экрана (ScreenshotShield & Android FLAG_SECURE)
* **Web ScreenshotShield:**
  * При потере окном фокуса (`window.onblur`) или сворачивании вкладки (`visibilitychange`) на весь экран накладывается плотный защитный фильтр размытия (`backdrop-blur-2xl`) с предупреждающим экраном.
  * Блокируются горячие клавиши системных утилит снятия скриншотов: `PrintScreen`, `Win+Shift+S`, `Cmd+Shift+3`, `Cmd+Shift+4`, `Cmd+Shift+5`.
  * Запрещены вызов контекстного меню (`contextmenu`) и перетаскивание элементов (`dragstart`).
* **Android OS Native Security:**
  * Флаг `WindowManager.LayoutParams.FLAG_SECURE` запрещает операционной системе делать скриншоты, блокирует захват видео и скрывает изображение приложения в карусели недавних окон (*Recent Apps*).

### 2.5 Защита от физического слежения (Randomized Virtual Keypad)
* Для предотвращения атак по тепловым следам на дисплее (*thermal smudge attack*) и подглядывания из-за плеча (*shoulder surfing*) виртуальная цифровая клавиатура оснащена переключателем **«Случайный порядок клавиш»**. Координаты цифр перемешиваются псевдослучайным образом при каждом запуске.

### 2.6 Биометрия (Android BiometricPrompt & Keystore)
* Многоразовый компонент `BiometricAuthOverlay` эмулирует двухфакторную биометрию Android:
  * **Сканер отпечатков пальцев (Fingerprint)**: тактильный отклик, проверка криптографического объекта в Keystore.
  * **Распознавание лица (Face Unlock)**: сканирование через камеру с наложением видоискателя и анимированного лазерного луча.

## 3. Руководство пользователя (User Manual)

### Шаг 1: Создание или восстановление
1. На стартовом экране выберите **«Создать новый кошелек»** для генерации нового мастер-ключа.
2. Если у вас уже есть резервная копия, выберите **«Восстановить кошелек»**.
3. Если зашифрованный кошелек уже сохранен в этом браузере, появится кнопка быстрого входа по PIN-коду.

### Шаг 2: Выбор энтропии (12 vs 24 слова) и дисклеймер
1. Выберите желаемую длину мнемоники:
   - **12 слов (128 бит):** Рекомендуемый выбор по умолчанию. Быстро переписывать, общепринятый стандарт индустрии.
   - **24 слова (256 бит):** Максимальный военный стандарт энтропии.
2. Внимательно прочтите дисклеймер о некастодиальности: восстановить средства через сервер невозможно.
3. Отметьте подтверждающий чекбокс личной ответственности и нажмите **«Сгенерировать фразу»**.

### Шаг 3: Запись мнемоники и печать Cold Storage PDF-паспорта
1. Слова отображаются в виде нумерованных карточек. Перепишите их по порядку слева направо.
2. **Экспорт PDF-паспорта:** Нажмите **«PDF-паспорт»**, чтобы сформировать защищенный документ формата A4 с векторным QR-кодом для холодного хранения.
3. **Android Share:** На мобильных устройствах доступна отправка документа через системную шторку файлов и Google Drive.
4. **Копирование:** Кнопка «Копировать всю фразу» защищена таймером автоочистки буфера обмена.
5. Нажмите **«Я записал фразу · Проверить»**.

### Шаг 4: Контрольная верификация 3 случайных слов
1. Система попросит подтвердить 3 случайно выбранных слова из фразы (например, слово #3, #7 и #11).
2. Для каждого слова выберите верный вариант из 5 предложенных кнопок.
3. После успешного выбора всех трех слов раздастся тактильный виброотклик, и система перейдет к установке пароля.

### Шаг 5: Задание основного PIN и клавиатура против отпечатков
1. Введите 6-значный мастер-PIN на виртуальной клавиатуре.
2. *(Опционально)* Включите тумблер **«Случайный порядок клавиш»** для защиты от подглядывания.
3. Повторите PIN для завершения шифрования хранилища алгоритмом AES-256-GCM.

### Шаг 6: Настройка Панического PIN-кода (Duress PIN)
1. Введите альтернативный 4–6 значный код, **отличный от основного PIN**.
2. В случае угрозы физического принуждения ввод этого кода моментально уничтожит все ключи и данные кошелька.
3. Нажмите **«Зафиксировать и войти в кошелек»** (или «Пропустить»).

### Шаг 7: Работа в криптокошельке и биометрическая верификация
1. Главный экран отображает мультичейн-портфель (BTC, ETH, SOL), деривированные публичные адреса и историю операций.
2. **Верификация биометрии:**
   - В блоке «Центр безопасности» нажмите **«Verify Biometrics · Раскрыть seed-фразу»**.
   - Приложите палец к сенсору или используйте Face Unlock в окне `BiometricAuthOverlay`.
   - При успешной проверке секретная мнемоника будет безопасно расшифрована.
3. **Тестирование панического PIN:**
   - Нажмите **«Симуляция ввода Panic PIN»** и введите панический код. Кошелек мгновенно сотрет все ключи с отображением аварийного баннера.

### Шаг 8: Сценарии восстановления (Ввод, QR-сканирование, PDF-импорт)
1. На стартовом экране выберите **«Восстановить кошелек»**:
   - **Вкладка «Ввод фразы»:** Печатайте слова через пробел. Система предлагает автодополнение из словаря на 2048 слов и проверяет контрольную сумму. Доступна кнопка быстрой вставки из буфера обмена.
   - **Вкладка «QR-код»:** Сканируйте QR-код через камеру устройства или загрузите изображение сохраненного QR.
   - **Вкладка «PDF-паспорт»:** Загрузите сохраненный PDF-файл паспорта для автоматического парсинга фразы.

## 4. Инструкция для разработчиков: Plug-and-Play SDK

### 4.1 Интеграция в React / Next.js
Встроить компонент онбординга в любой React проект:

```tsx
import { useState } from 'react';
import { BIP39Onboarding } from '@/components/onboarding/BIP39Onboarding';
import { WalletCredentials } from '@/types/onboarding';

export function App() {
  const [wallet, setWallet] = useState<WalletCredentials | null>(null);

  if (!wallet) {
    return (
      <BIP39Onboarding
        config={{
          defaultWordCount: 12, // 12 или 24 слова
          allowPanicPin: true,  // активация Duress PIN
          allowPdfExport: true, // генерация PDF-паспорта
          appName: 'MyCryptoApp'
        }}
        onComplete={(credentials, pin, duressPin) => {
          console.log('Ключ получен:', credentials.masterFingerprint);
          setWallet(credentials);
        }}
        onPanicTriggered={() => {
          console.warn('Сработал Panic PIN! Все ключи стерты.');
          setWallet(null);
        }}
      />
    );
  }

  return <MyVaultDashboard wallet={wallet} />;
}
```

### 4.2 Нативный Android (Kotlin + Jetpack Compose)
```kotlin
// Android Kotlin + Jetpack Compose + StrongBox Keystore
@Composable
fun AndroidBip39Onboarding(
    onComplete: (credentials: WalletCredentials, pin: String) -> Unit,
    onPanicTriggered: () -> Unit
) {
    val activity = LocalContext.current as? Activity

    // 1. Аппаратный запрет скриншотов на уровне ОС
    DisposableEffect(Unit) {
        activity?.window?.setFlags(
            WindowManager.LayoutParams.FLAG_SECURE,
            WindowManager.LayoutParams.FLAG_SECURE
        )
        onDispose {
            activity?.window?.clearFlags(WindowManager.LayoutParams.FLAG_SECURE)
        }
    }

    // 2. Аппаратное шифрование через Android Keystore (StrongBox / TEE)
    val masterKey = MasterKey.Builder(LocalContext.current)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .setRequestStrongBoxBacked(true)
        .build()

    val securePrefs = EncryptedSharedPreferences.create(
        LocalContext.current, "vault_secrets", masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )

    // 3. Онбординг-пайплайн Jetpack Compose
    Bip39Flow(
        wordCount = 12,
        onFinished = { creds, pin -> onComplete(creds, pin) },
        onDuressWipe = {
            // Экстренное уничтожение ключей при вводе панического PIN
            securePrefs.edit().clear().commit()
            LocalContext.current.cacheDir.deleteRecursively()
            activity?.finishAffinity() // Моментальное закрытие приложения
            onPanicTriggered()
        }
    )
}
```

### 4.3 Деривация Web3 аккаунтов (EVM, Solana, Bitcoin)
```typescript
import { HDNodeWallet } from 'ethers';

// Деривация Ethereum / EVM кошелька по стандартному пути BIP-44
export function deriveEthereumWallet(mnemonic: string) {
  const wallet = HDNodeWallet.fromPhrase(mnemonic, undefined, "m/44'/60'/0'/0/0");
  return {
    address: wallet.address,
    privateKey: wallet.privateKey
  };
}
```

## 5. Универсальные системные промпты для AI-кодеров

### Промпт №1: Мгновенное внедрение онбординга (Cursor, Windsurf, Claude, Copilot)
```text
Ты — ведущий Web3 и Security инженер. Твоя задача — интегрировать готовый production-grade BIP-39 онбординг-модуль в текущее React/Next.js приложение.

Требования к интеграции:
1. Использовать готовый компонент <BIP39Onboarding config={...} onComplete={handleWalletReady} onPanicTriggered={handleEmergencyWipe} />.
2. Поддержать выбор 12/24 мнемонических слов (128 / 256 бит энтропии по BIP-39).
3. Обеспечить обязательный экран дисклеймера с личной ответственностью пользователя и блокирующим чекбоксом.
4. Включить защиту от скриншотов: при потере фокуса окна (window.blur) или нажатии клавиш PrintScreen / Cmd+Shift+S накладывать плотный blur-shield с предупреждением.
5. Реализовать экспорт Cold Storage PDF-паспорта со списком слов и встроенным QR-кодом для быстрого восстановления.
6. Обязательная интерактивная верификация: случайно выбрать 3 слова из фразы; для каждого предложить 5 кнопок (1 верное + 4 дистрактора из словаря BIP-39).
7. Задание 6-значного мастер-PIN с шифрованием AES-GCM (256-бит, PBKDF2 100,000 итераций).
8. Задание отдельного Панического PIN-кода (Duress PIN): при его вводе все ключи и локальные данные мгновенно и безвозвратно стираются, а приложение сбрасывается в исходное состояние.
9. Поддержать 3 пути восстановления: ручной ввод с автодополнением по словарю, сканирование QR-кода с камеры/файла и загрузку PDF-паспорта.
10. По завершении передать объекту хост-приложения деривированные аккаунты (BTC, ETH, SOL), seedHex и мастер-отпечаток (fingerprint). Не сохранять приватные ключи в незашифрованном виде.
```
